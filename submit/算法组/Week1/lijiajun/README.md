- 抖动分析：连续画面比单张更容易抖，原因有三条。① 单帧噪声会让掩膜边界逐帧收缩/膨胀，`boundingRect` 的中心跟着跳 1~3 像素；② 同一帧里出现多个面积相近的候选时，最大轮廓会在两个候选之间来回切，中心直接跳上百像素（这次演示里有 8 帧跳超过 50 像素）；③ 目标本身在动，这是真实位移，不该被平滑掉。
- 抑制手段：面积过滤先砍掉小碎片（任务三的 `AREA_RATIO`）；再对中心点做 EMA：`s = (1-α)·s + α·c`，`α=0.35`；连续 8 帧无目标就清空平滑值，避免重新检出时从旧位置滑过来。
- α 怎么定的：`python src/task4_camera.py --bench` 用 test5 模拟手持抖动（每帧随机平移 ±3 像素 + σ=4 噪声）跑 150 帧，测中心点逐帧位移：

  | α | 平滑后逐帧位移均值 | 平滑点与真实中心的偏差 |
  |---|---|---|
  | 不平滑 | 3.13 px | 0 |
  | 0.2 | 0.48 px | 1.80 px |
  | 0.35 | 0.87 px | 1.52 px |
  | 0.5 | 1.30 px | 1.21 px |

  取 0.35 是折中：抖动压掉约 72%，滞后约 1.5 像素，对球这类目标够用；要更稳可以换卡尔曼，但本周先用最简的。

## 四、一次失败案例与改进思路

- 现象：test6 一开始给蓝色杯子设的范围是 `H 88~118、S≥60、V≥40`，mask 图里杯口一圈和把手的高光全是黑的，画出来的框只有杯身中间一块，面积 23852，杯子明显没框全。
- 我是怎么查的：把这组范围跑出来的 mask 和原图叠在一起看，丢掉的是杯沿、把手这些偏亮的区域；再把这两块的像素 HSV 直接打印出来，S 只有 40~50（高光接近白色，S 天然低），刚好被 `S≥60` 切掉。又扫了一遍 `S≥40 / 50 / 60 / 80` 四组，每组记白像素数和最大轮廓面积。
- 原因：S 表示“离灰色有多远”，杯口高光接近白色，S 天然低，把 S 下限当成“去掉灰色背景”的手段，会把目标最亮的部分一起切掉。
- 改进：S 下限从 60 降到 40，H 收窄到 88~118；代价是 inRange 白像素变多、候选轮廓涨到 24 个，再用面积阈值 1.0%（2621 像素）兜底。
- 改进后效果：杯身 + 把手完整框住，面积 23852 → 33964，5 张测试图都能跑出合理掩膜。仍然会误检：桌上的蓝色小杯子被当成第二个目标，test4 的桌面焦散斑也去不掉。这两处要么是“颜色一样但物体不同”，要么是“光源和物体同色”，颜色法本身解决不了，得靠形状、深度或者时序来分辨。
